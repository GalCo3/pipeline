Run tools/scripts/port-forward.sh first.

These are the ports it uses when they are free. When one is already taken —
Docker Desktop binds several of them itself, at the Service's own port — the
script moves that service to port + 10000 (9200 -> 19200) and prints the address
it actually used. Trust the script's output over this file in that case.

Keycloak is the exception: its issuer URL is baked into the token, so it has to
be on 8083. If the script reports it on 18083, free 8083 rather than using the
fallback — the login will fail on an issuer mismatch. dls-console is the same
kind of exception for the other half of the handshake: the realm registers
exactly `http://localhost:8086/api/auth/callback/keycloak`, so on the fallback
port the login fails with `invalid_redirect_uri`.

No port-forward needed: to reach a service from inside the cluster, run a
throwaway pod on its network, e.g.
  kubectl -n hermes run curl --rm -i --restart=Never \
      --image=curlimages/curl:8.11.1 -- -sS http://elasticsearch:9200
